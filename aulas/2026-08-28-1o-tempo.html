Chaves, domínio e integridade

Como distinguir registros e manter os dados coerentes.

28/08/20261º TEMPOSALA07:00 às 07:50

1. O problema

Observe dois registros da Central de Avisos:

id?Título: Reunião
id?Título: Reunião

Como saber exatamente qual registro queremos consultar, alterar ou excluir?

O título ajuda a entender o aviso, mas pode se repetir. Precisamos de uma informação criada especialmente para distinguir cada ocorrência.

2. Identificador

Um identificador é uma informação que permite reconhecer uma ocorrência sem confundi-la com outra.

Exemplo

id_aviso: 1Título: Reunião
id_aviso: 2Título: Reunião

Os títulos são iguais, mas os identificadores mostram que são registros diferentes.

3. Chave primária

Definição

Chave primária é o atributo ou conjunto de atributos usado para identificar de forma única cada registro.

id_aviso = 1id_aviso = 2

Neste exemplo, id_aviso é a chave primária. Cada aviso recebe um valor que o diferencia dos demais.

4. Unicidade

Unicidade significa que o valor usado para identificar um registro não pode se repetir.

Identificação adequada
id_aviso: 1id_aviso: 2
Identificação repetida
id_aviso: 1id_aviso: 1

Se os dois avisos têm identificação 1, qual deles seria alterado?

5. Domínio dos dados

O domínio define quais valores são esperados e aceitos para um campo. Uma data deve receber uma data possível; um horário deve representar um horário possível.

Adequados
data: 28/08/2026horário: 09:40
Inadequados
data: bananahorário: 25:90

Que tipo de valor o campo “responsável” deveria aceitar?

6. Obrigatoriedade

Alguns campos precisam ser preenchidos para que o registro faça sentido. Outros podem ser opcionais, dependendo das regras combinadas para o sistema.

Na Central de Avisos

  • Um aviso sem título seria compreensível?
  • A data deve ser sempre obrigatória ou existem avisos sem data definida?
  • Quem decide essas regras? A equipe que conhece o objetivo do sistema.

7. Integridade

Ideia principal

Integridade é o conjunto de regras usado para manter os dados válidos, completos e coerentes.

Unicidade, domínio e obrigatoriedade são exemplos de decisões que ajudam a proteger a qualidade dos dados.

8. Integridade de entidade

Cada registro precisa possuir uma identificação válida e única. A identificação não pode estar vazia e não pode ser compartilhada por dois registros.

Atenção: sem uma identificação válida, o sistema não consegue distinguir aquela ocorrência com segurança.

9. Atividade rápida

Para cada situação, identifique o problema e escreva a regra que poderia evitá-lo.

  1. Dois avisos foram cadastrados com id_aviso = 7.
  2. O campo data recebeu o valor semana que vem talvez.
  3. Um aviso foi salvo sem título.
  4. O campo horário recebeu 18:30. Há algum problema?

Verifique sua aprendizagem

Classifique cada caso como: chave repetida, dado inválido, campo importante vazio ou dado adequado.
