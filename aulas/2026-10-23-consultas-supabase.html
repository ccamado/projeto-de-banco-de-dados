Objetivo e contexto

Dar continuidade aos conhecimentos já desenvolvidos no bimestre, executar testes verificáveis e documentar resultados sem repetir etapas anteriores.

Material produzido para aula planejada; sua publicação não confirma aula ministrada. Não exponha senhas, dados reais ou chaves administrativas.

Abrir o SQL Editor do Supabase ↗

Roteiro da prática

  1. Abra seu próprio projeto Supabase e confirme a estrutura criada na atividade de 09/10.
  2. No SQL Editor, veja os nomes reais das tabelas; execute consultas SELECT simples sobre sua tabela de avisos.
  3. Adicione WHERE e ORDER BY. Em seguida, faça uma consulta JOIN usando as chaves reais do seu DER.
  4. Anote quantidade de linhas retornadas e explique um resultado vazio. Salve o arquivo SQL e uma captura sem dados pessoais.

Código, comandos ou modelo de trabalho

-- Adapte os identificadores se o script de 09/10 usou nomes diferentes.
-- 1. Leia avisos já cadastrados.
SELECT * FROM avisos LIMIT 10;

-- 2. Ordene pelo identificador (confira se existe coluna id).
SELECT * FROM avisos ORDER BY id DESC LIMIT 10;

-- 3. Investigue a estrutura das tabelas antes do JOIN.
SELECT table_name, column_name, data_type
FROM information_schema.columns
WHERE table_schema = 'public'
ORDER BY table_name, ordinal_position;

Entregas e critérios

Entregue: arquivo de código, script ou quadro comparativo; evidência dos testes; uma conclusão de 3 a 5 linhas descrevendo o que funcionou, o que falhou e como corrigiu.

Critérios: execução/conceitos corretos (40%), testes e interpretação (30%), documentação (20%), autonomia e cooperação (10%).
